# 在图上指定父节点

新建真实会话后，输入区和图谱工具栏都可以选择本轮模式：

| 模式 | 直接父节点 |
| --- | --- |
| 自动判断 `auto` | 使用现有自动选择策略 |
| 自动 + 指定 `augment` | 指定集合与自动结果取并集，指定节点优先保留 |
| 仅指定 `manual` | 严格使用指定集合，跳过自动选择器；空集合表示独立话题 |

点击输入区“在图中选择父节点”，再点击画布节点进行多选。也可以直接使用节点上的加号。选中的节点会突出显示，输入区显示可移除的标签。选完点击完成，输入新问题并发送。普通浏览点击仍只负责定位问答。手机上进入选择会切到图谱，完成或取消会回到聊天。

“仅指定”约束的是**直接父节点**。上下文策略仍会展开这些节点的祖先，并按预算使用原文、截取摘要或省略内容。指定父边并不保证整段原文一定进入上下文；实际采用内容与省略记录在上下文检查中可见。

## 调整已有回答

1. 在图中定位要调整的节点，点击“调整父节点并重新生成”。聊天记录与上下文面板也提供入口。
2. 当前父节点会被预选。切换模式、增加或移除父节点；自身、下游及过期节点不能新选为父节点。
3. 完成图上选择，提交“重新生成回答”。原问题只读，尚未发送的新问题草稿保留；取消会恢复之前的新问题父节点设置。

生成成功后，同一个节点的回答版本加一，父边替换，画布自动布局。可以选择后来创建、且不会形成环的无关节点为父节点；轮次编号表示创建顺序，连线表达依赖顺序。

所有下游节点标记“待更新”，保留原回答与实际上下文，不会自动重新调用模型。要继续使用这些节点作为新问题的父节点，先逐步重新生成受影响节点，或为它们改用有效的依赖。上下文检查里的“查看历史版本”可以查看旧回答及父节点，版本 API 同时保留完整上下文记录。

生成失败或并发冲突时，原回答、拓扑和版本保持不变，当前选择保留以便调整或重试。409 表示图已被其他请求修改，应先刷新再重试。示例会话只读，不能指定或重新生成。

## API 示例

新增一轮，指定父节点并允许自动补充：

```http
POST /api/conversations/{conversation_id}/turns
Content-Type: application/json

{
  "question": "结合这两个方向给出方案",
  "parent_mode": "augment",
  "parent_ids": ["node-a", "node-b"]
}
```

重新生成已有节点，直接父节点严格使用指定集合：

```http
POST /api/turns/{node_id}/regenerate
Content-Type: application/json

{
  "parent_mode": "manual",
  "parent_ids": ["node-b"],
  "expected_revision": 1
}
```

新增返回 `TurnNode`，重新生成返回完整 `ConversationGraph`。`GET /api/turns/{node_id}/versions` 按版本升序返回历史与当前 `TurnNode`。`ContextItem.revision` 指向生成时实际读取的来源版本；当前图连线不能替代历史上下文快照。

父节点 ID 必须同属本会话、存在、互不重复且未过期，一次最多指定 64 个。`auto` 模式不能携带非空 `parent_ids`。非法父节点或成环请求在调用模型前返回 422；目标不存在返回 404；修订冲突返回 409；上游模型失败返回 502。

旧 SQLite 数据库打开时自动补充表与整图修订字段；旧节点默认为 v1，版本记录按需补存。新增和重新生成均使用事务及整图修订号防止并发覆盖。

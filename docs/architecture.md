# LATTICE 架构设计

当前目标是提供可运行、可替换策略、可检查上下文的研究骨架。默认行为是基线实现，未完成部分在代码和 ROADMAP 中标记 TODO。

## 两种图

### 执行图

LangGraph 管理每次新问题的处理步骤：

```text
load_history → select_parents → build_context → answer → persist
```

`answer` 内部调用 LangChain `create_agent`。如果回答模型请求工具，LangChain 执行工具并将结果交还模型，直到模型给出答案或到达执行限制。执行图描述程序如何运行，可以包含循环；一个新问题不会在这个执行图中永久新增一个处理节点。

### 对话依赖 DAG

对话 DAG 是存储层中的历史数据：

- 一个节点是一轮用户问题及助手回答。
- 一条父 → 子边表示生成当前版本前选择的依赖，可自动判断或由用户指定。
- 新问题可以有零个、一个或多个父节点。
- 新问题引用同一会话已存在的节点；重新生成可引用之后创建的无关节点，但不能引用自身和任何下游节点。

后端对自身和可达下游的排除保证图无环。多父节点不要求把历史复制到多个分支；共享祖先按节点 ID 去重。

重新生成保持节点 ID、问题与轮次，增加 `revision`，保存旧版本并替换当前回答及入边。出边保留，所有下游节点标记 `stale`，其回答和上下文快照保持原样。删除节点和修改原问题尚未实现。

## 单轮数据流

1. **读取历史**：从 SQLite 获取会话信息和已完成的历史节点。
2. **选择父节点**：`auto` 使用启发式或 LLM 选择器；`augment` 将指定节点与自动结果合并；`manual` 跳过选择器，仅使用指定的直接父节点。先校验指定节点，再进行任何模型调用。过期节点、自身及下游不进入自动候选。
3. **构造上下文**：从父节点求祖先闭包，按拓扑顺序（同层以轮次稳定排序）组装，记录来源版本，选择原文或截取摘要并控制预算。被省略的节点保留 ID 记录。
4. **回答**：将系统指令、会话指令、选定历史和当前问题交给 LangChain agent。工具只服务于当前回答执行。
5. **保存**：回答成功后保存新节点、选择信息、实际上下文和依赖边，并将节点返回调用方。

父节点识别发生在回答前，输入只包含当时已存在的历史与当前问题。`ParentSelection.mode` 与 `requested_parent_ids` 明确记录自动和人工控制；选择器回退路径与依据同时保留。

## 策略边界

### 父节点选择

默认启发式适合验证控制流：它不是语义依赖模型，也不保证选中回答所需的全部信息。中文字符重合、词重合和指代性回退会产生误连或漏连。候选数、阈值和最大父节点数通过 YAML 配置。

LLM 选择器是另一条可用基线，尚未解决联合证据覆盖、代词消解、置信度校准等研究问题。非法 ID 不能创建边；选择失败会记录原因，并使用默认策略继续。

选择器有独立的 `routing.max_input_tokens` 预算，会在模型调用前裁剪候选摘要。
若系统提示和当前问题已耗尽该预算，不会发出选择器请求，而是明确记录回退原因。
回答阶段也会在选择器运行前预检当前问题，避免超长输入先触发一次付费调用再被拒绝。

策略输出采用 `ParentSelection`，包括 `parent_ids`、`strategy`、`reason`、`candidate_ids`、`mode`、`requested_parent_ids` 和可选 `fallback_reason`。指定节点不会被自动选择器的 `max_parents` 截掉；请求最多指定 64 个不同节点。

### 上下文管理

`ContextBundle` 单独记录模型本轮获得的历史表示。它与父节点列表不相同：一个父节点可能引入多个祖先，也可能因预算只提供摘要。

当前预算实现保留系统指令、当前问题及执行开销的空间，再分配历史。超长问题或固定输入已超出预算时应拒绝请求，避免默默截断用户问题。历史仍可因预算被截取或省略。

当前 token 数是基于 UTF-8 字节的保守估算，不是对应模型的精确 tokenizer。这个预算用于框架内选择，不构成提供商实际上下文上限或计费 token 的保证。截取摘要有信息损失；保存完整原文只是为回溯和未来重建提供基础，不意味着当前回答已经读取全部历史。

启用 `context_manifest` 时，组装阶段为工具定义和本轮工具交换预留空间；每次模型调用前再检查消息及工具元数据。
`context.items` 保存历史输入，`metrics.execution_trace` 保存本轮模型与工具产生的消息。
`answer_usage` 仅汇总回答 agent 的提供商用量；选择器用量及完整费用统计仍是 TODO，不能据此声称端到端节省了多少费用。

后续可以替换：

- 候选召回器和联合父节点选择器。
- 查询相关的节点摘要生成器。
- 原文／片段／摘要的预算分配算法。
- 针对模型的 tokenizer 和本轮执行预算管理。

### 回答 Agent

模型适配层提供 `mock`、`openai_compatible` 和可选 `anthropic`。LangChain 负责标准消息、工具调用与返回格式。

`context_manifest` 是只读演示工具，用于查看本轮已经选择的上下文清单。它不会检索新的会话，不会修改图，也不会执行 shell。默认 mock 请求该工具一次，再返回可预测的回答，以便离线验证模型 → 工具 → 模型这一闭环。

`agent.enable_context_tool: false` 会关闭该工具，适合暂未配置工具调用能力的本地模型；外层自动选父节点与上下文构造继续执行。真正的检索、浏览器、代码等工具留有后续扩展空间。

## 模型与配置

`models.answer` 与 `models.selector` 独立：回答可使用高质量模型，选择可使用较小模型。选择器为 `null` 时复用回答模型配置；启发式路由不会调用选择模型。

模型对象在实际使用时构建；配置解析本身不请求上游服务。密钥优先从指定环境变量读取，`.env` 仅作为本地开发便利。相对数据库路径按 YAML 所在目录解析，确保从不同工作目录启动时仍指向同一数据文件。

OpenAI-compatible 接入依赖服务对相应消息、参数、工具协议的实现。本地 vLLM 的模型名、服务地址、chat template 和工具解析器由用户部署的服务决定。框架不负责启动或下载模型。

## 持久化与接口

SQLite 保存：

- `Conversation`：标题、会话指令、创建时间及整图修订号。
- `TurnNode`：轮次、完整问答、摘要、父节点、选择结果、回答版本及过期状态。
- `turn_versions`：历次回答与实际上下文快照；过期标记本身不产生新回答版本。
- 依赖边：父节点到子节点的有向关系。
- 上下文清单：采用了哪些历史表示、哪些节点被省略及估算预算。

同会话新增和重新生成都在 SQLite 事务内比较整图修订号并提交；即使节点数没有改变，也能发现其他 worker 的更新。并发冲突返回 409，让调用方重新读取后重试。模型失败不会改动回答、拓扑、版本或下游状态。已有数据库自动迁移字段及表，旧回答版本按需补存。

FastAPI 接受可选的 `parent_mode` 和 `parent_ids`。重新生成还可提交目标 `expected_revision`，并返回完整更新后的图。版本接口按升序返回历史及当前问答。前端使用返回的 `selection` 和 `context` 显示依赖、选择依据与实际上下文；历史来源可按节点 ID 与版本追溯。

完整路由见 README 和运行中的 `/docs`。当前请求在回答持久化后返回完整 JSON；流式事件协议和公开服务认证仍待实现。

## 前端与后端的连接

`frontend/` 使用 React、TypeScript、Vite 和 React Flow。普通点击图节点定位问答；开启选择模式后，点击节点切换指定父节点，显示选中样式与待提交的连线。重新生成时自身和下游不可选，提交成功后读取完整图并自动布局。选择与预览不写数据库，取消恢复之前的新问题设置。上下文面板可读取历史版本。自动布局只影响屏幕坐标，不修改依赖关系。

真实会话通过同源的 `/api` 访问后端，SQLite 是持久化数据来源。内置示例仅用于只读查看界面，不会调用聊天接口或将样例节点写入数据库。默认 mock 服务和真实模型共享同一套协议；界面展示当前模式，mock 文本不能用来评估回答质量。

开发模式由 Vite 运行前端，将 `/api` 和 `/healthz` 代理到后端；`LATTICE_API_TARGET` 可替换默认的 `http://127.0.0.1:8000`。生产构建写入 `frontend/dist/`，FastAPI 在启动时发现其中的 `index.html` 后提供静态文件，API、健康检查和文档路由优先于静态路由。不存在的 `/api` 路径始终返回 JSON 404。没有构建产物时，后端仍可独立运行。

模型调用、父节点识别和上下文预算全部发生在后端。前端不持有模型服务密钥，不依靠浏览器存储重建研究数据。当前只有完成态 JSON，因此页面能显示请求等待和完成后的实际结果，无法展示尚未由服务端发布的选父或 token 事件。

## 可观测信息的含义

需要区别三种关系：

| 信息 | 说明 |
| --- | --- |
| `parent_ids` | 选择器认为本轮依赖的历史节点 |
| `context.items` | 预算管理后实际传入的历史原文或摘要 |
| 模型最终回答 | 模型读取所给上下文后生成的内容 |

选择记录不是经过证明的因果依赖。出现在 prompt 中也不等于模型实际使用了该信息。因此，后续研究需要证据删除、替换和任务结果等实验，而不能只以画出的连线判断方法有效。
